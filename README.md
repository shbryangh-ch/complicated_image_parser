# Building a Local AI for Complex Image Parsing
# 我是如何打造能解析複雜圖片的本地 AI
(不用自己寫prompt)

## 專案介紹

本專案的目標是打造一套能在本地環境執行的 AI，讓開源本地大型語言模型（Local LLM）能夠解析包含大量文字、密集表格、相似欄位、虛線框與複雜版面配置的圖片，並將解析結果轉換成結構固定、可供後續程式使用的資料。

這類任務不只是辨識圖片中的文字。AI 還必須理解文字與版面區域之間的關係、判斷資料所屬欄位、遵守指定的擷取規則，並確保輸出結果完整且符合格式要求。

例如，在報關文件解析任務中，即使模型能夠辨識圖片中的大部分文字，仍可能發生欄位錯置、資料遺漏、相似代碼混淆，或 CSV 欄位數量不正確等問題。

因此，本專案不只是嘗試讓模型「看懂圖片」，而是要建立一套能夠正確擷取資料、依照規則完成判斷，並產生可靠結構化輸出的本地 AI。

## 專案挑戰：從辨識文字到正確解析資料

複雜圖片解析通常需要同時處理多個層面的問題：

- **文字辨識：** 正確讀取文字、數字、英文代碼與特殊符號。
- **版面理解：** 判斷文字的位置，以及文字與標題、框線和相鄰欄位的關係。
- **欄位對應：** 根據欄位名稱、位置與指定規則，選取正確的資料。
- **資料完整性：** 避免遺漏內容、欄位或必要的空值。
- **格式正確性：** 確保輸出符合指定欄位數量、順序及 CSV 格式。
- **結果驗證：** 找出不確定的內容，並檢查容易發生錯誤的欄位。

這些問題顯示，文字辨識只是整個解析流程的一部分。要讓本地 AI 真正完成任務，還需要讓模型依照明確的規則處理文字、欄位關係與輸出結果。

## 關鍵發現：為什麼同一份任務描述會產生不同結果？

在實際測試中，使用 ChatGPT 與開源本地 LLM 執行相同任務時，即使提供相同的原始指令，仍可能得到不同品質的結果。

ChatGPT 能夠在較模糊的指令下，成功推導出完成任務所需的操作；但在相同任務中，本地模型可能仍會遺漏資料、混淆欄位，或忽略輸出格式的細節。

**ChatGPT 能從較模糊的指令中推導出完成任務所需的操作；開源本地 LLM 則可能需要將這些隱含的操作、判斷規則與驗證步驟明確寫出來。**

這成為本專案改善本地圖片解析能力的重要切入點。

問題不一定只是本地模型的文字辨識能力不足，也可能是原始 Prompt 沒有明確描述完成任務所需的全部操作。對 ChatGPT 而言，部分要求可能可以從上下文推導出來；對本地模型而言，這些要求可能需要被拆解成更具體的指令。

因此，本專案採取的方向不是單純增加 Prompt 的長度，也不是只要求模型「更加仔細」，而是先讓 ChatGPT 成功完成任務，再請 ChatGPT 將完成任務所需的操作整理成改進 Prompt，交由本地模型實際測試。

這個方法的目的，是將成功解析所需的操作、欄位規則與驗證條件，轉化成可明確描述、可重複執行的規格，逐步改善本地 AI 的解析品質。

## 核心方法：基於實際執行流程的 Prompt 萃取

本專案將這套方法稱為 **Execution-Based Prompt Distillation（基於實際執行流程的提示詞萃取）**。

核心概念是：不只要求 AI 改寫一份 Prompt，而是先取得成功完成任務的結果，再請 ChatGPT 回顧完成任務的方法，將相關操作與判斷整理成更適合目標本地模型的 Prompt，最後以相同測試資料驗證改善效果。

### 開發流程

```text
原始任務與模糊 Prompt
          |
          v
ChatGPT 成功完成任務
          |
          v
分析成功結果與可觀察的操作要求
(請 ChatGPT 把它完成任務的流程寫成改進 Prompt)
          |
          v
萃取欄位規則、判斷條件與驗證步驟
          |
          v
產生目標本地模型專用 Prompt
          |
          v
使用相同測試資料執行本地模型
          |
          v
比較正確答案、資料缺漏與欄位錯置
          |
          v
修訂規則並進行回歸測試
```

### 1. 先讓 ChatGPT 成功完成任務

使用原始任務描述與模糊 Prompt，讓 ChatGPT 完成複雜圖片解析，並保留成功結果作為參考。

這個階段的重點是確認預期輸出，而不是一開始就撰寫所有規則。

### 2. 請 ChatGPT 將完成任務的方法整理成改進 Prompt

在取得成功結果後，請 ChatGPT 根據任務需求與實際結果，整理完成任務所需的操作、判斷規則及檢查步驟，並將它們寫成改進後的 Prompt。

這一步是整個方法的關鍵：從原本只描述「要完成什麼」，進一步整理出「需要執行哪些操作，才能更可靠地完成任務」。

這裡整理的是可描述、可驗證的任務操作要求，而不是宣稱能完整還原 ChatGPT 的內部推理過程。

### 3. 萃取欄位規則、判斷條件與驗證步驟

將改進 Prompt 中的要求整理成清楚的規格，包括：

- 每個欄位的定義與資料來源。
- 如何根據標題、位置、框線及上下文判斷欄位歸屬。
- 如何處理容易混淆的文字、數字與代碼。
- 如何避免遺漏資料及錯誤處理空欄位。
- 如何確認輸出欄位數量、順序與格式正確。
- 遇到不確定內容時，應如何重新檢查，而不是直接猜測。

這些規格可以依照實際測試中發現的問題持續補充，不必一次完成所有規則。

### 4. 產生目標本地模型專用 Prompt

根據目標模型的實際表現，將上述規格組織成適合本地模型使用的 Prompt。

例如，若模型經常將相鄰區域的文字放入錯誤欄位，就應補充明確的欄位判斷條件；若模型經常遺漏空欄位，則應明確規定輸出時必須保留所有欄位位置。

目標不是讓 Prompt 無限制地變長，而是讓關鍵要求足夠明確，並能針對已知錯誤提供有效的約束。

### 5. 使用相同測試資料執行本地模型

將改進後的 Prompt 交給目標本地 LLM，使用與基準測試相同的圖片與輸入條件執行任務。

透過固定測試資料，才能比較修改前後的結果，避免將不同圖片的難度差異誤認為 Prompt 的改善效果。

### 6. 比較正確答案、缺漏與欄位錯置

將本地模型輸出與參考答案進行比較，記錄錯誤類型及發生位置，例如：

- 文字辨識錯誤。
- 欄位對應錯誤。
- 必要資料遺漏。
- 相似字元或代碼混淆。
- CSV 欄位數量或結構錯誤。

透過分類錯誤，可以更有針對性地修改 Prompt，而不是每次都重新撰寫整份指令。

### 7. 修訂規則並進行回歸測試

針對測試中發現的錯誤修訂 Prompt，並重新執行原有測試案例。

每次修改都應保留版本、修改原因與測試結果，確認新規則不只修正了目前的問題，也沒有讓原本正確的案例產生新的錯誤。

如此便能形成持續改善的循環，逐步提高本地 AI 在指定解析任務上的穩定性。

## 解析品質的評估方式

本專案重視實際解析結果，而不只看模型是否產生看似合理的文字。

| 評估項目 | 檢查內容 |
|---|---|
| 文字辨識準確度 | 字元、數字與代碼是否正確 |
| 欄位對應正確率 | 資料是否被放入正確欄位 |
| 資料完整率 | 必要資料是否有遺漏 |
| 欄位結構正確性 | 欄位數量與順序是否符合規格 |
| CSV 有效性 | 特殊字元、逗號、引號與空欄位是否正確處理 |
| 回歸測試結果 | 修改後是否維持既有案例的正確性 |

這些指標能協助判斷改善來自哪個環節，並為後續 Prompt 修改提供具體依據。

## 專案目標

本專案的最終目標，是建立一套能在本地環境實際運作的複雜圖片解析 AI，並讓這套系統能透過測試與錯誤分析持續改善。

- 解析包含密集文字、表格及複雜版面配置的圖片。
- 根據明確的欄位規則正確擷取與分配資料。
- 輸出符合指定結構的 CSV 或其他格式。
- 透過 Prompt 萃取與錯誤分析降低資料缺漏及欄位錯置。
- 建立可重複執行的測試、版本管理與回歸驗證流程。
- 將成功案例累積的經驗整理成可重複使用的解析規格。

本專案並不假設只靠 Prompt 就能讓所有本地模型完全達到 ChatGPT 的能力，而是透過明確化任務要求、實際測試與持續修正，縮小本地模型在特定複雜圖片解析任務上的執行差距。

**最終目標是做出能在本地環境執行、能依照規則正確解析複雜圖片，並能透過實際測試持續改善的 AI。**
